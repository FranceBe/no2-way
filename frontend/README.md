# Frontend

React + TypeScript app built with Vite. It shows London weather, air quality and transport data served by the API in `../backend`.

Use the Node version from `../.nvmrc` (`nvm use`).

The repo is an npm workspace: run `npm install` once **at the root**, which installs `shared/`, `backend/` and `frontend/` together (one lockfile, one TypeScript, one ESLint). API response types come from `@no2-way/shared` (`../shared/src/index.ts`); `apiFetch('/air')` infers its result type from the path.

On `git commit`, the hook in `../.husky/pre-commit` runs lint-staged: staged files under `frontend/`, `backend/` or `shared/` go through that workspace's `lint-staged.config.js` (lint, type-check, tests with coverage thresholds, build). `npm run coverage` shows the same numbers.

## Scripts

| Command             | What it does                                                               |
| ------------------- | -------------------------------------------------------------------------- |
| `npm run dev`       | Dev server with mocked API (MSW)                                           |
| `npm run build`     | Type-check and production build, against the real API                      |
| `npm run lint`      | ESLint                                                                     |
| `npm run storybook` | Component library on http://localhost:6006                                 |
| `npm test`          | All Vitest projects in watch mode (unit + stories)                         |
| `npm run test:unit` | Unit tests only (jsdom)                                                    |
| `npm run test:e2e`  | Playwright end-to-end tests (`npx playwright show-report` after a failure) |

## API and mocks

The API URL and the mock switch come from `.env.development` and `.env.production`:

- In dev, `VITE_USE_MOCKS=true`: [MSW](https://mswjs.io) answers every request with generated data from `src/shared/api/mocks/`.
- To use the real API in dev, run `VITE_USE_MOCKS=false npm run dev`, or put `VITE_USE_MOCKS=false` in `.env.development.local` (not committed).

`public/mockServiceWorker.js` is generated by MSW: don't edit it. If mocks stop working after an `npm install`, regenerate it with `npx msw init public`.

## Project structure

```
src/
  main.tsx           entry point: router, react-query, MSW in dev
  app/               the application shell
    routes/          route table, redirect to the first tab
    layout/          AppLayout (header, tabs, outlet), ThemeToggle
    tabs/            the tab bar
    pages/           one folder per tab: composes the features it shows
  features/          one folder per feature, independent from each other
    air-quality/
    weather/
    transport/
  shared/            used by several features or by the app
    api/             fetch client, react-query queries, MSW mocks (dev only)
    theme/           design tokens, global styles, light/dark logic
    location/        selected neighbourhood (?location=…) and its picker
    time/            London time parsing and formatting
    test/            test setup: MSW server, renderWithProviders
e2e/                 Playwright scenarios
```

Inside a feature:

```
features/transport/
  index.ts           public entry point: the app imports from here only
  components/
    DeparturesBoard/ DeparturesBoard.tsx, .css, .test.tsx, .stories.tsx
    …                one folder per component, with everything that belongs to it
  hooks/             the feature's hooks
  utils/             pure logic, each file next to its test
  fixtures/          data for tests and stories (when needed)
```

Conventions:

- **Imports**: relative inside an area (a feature, `app/pages`, `shared/api`…), `@/…` across areas (`@/shared/api/queries`, `@/features/transport`). The alias is declared in `tsconfig.app.json` and `vite.config.ts`.
- **Dependencies go one way**: `app` → `features` → `shared`. A feature never imports another feature; what two features need moves to `shared/`.
- **The app only uses a feature's `index.ts`**. Tests and stories may import its `utils/` and `fixtures/` directly.

## Design system

All colours live in `src/shared/theme/tokens.css` (light and dark). See **Design System/Tokens** in Storybook for the palette and typography. Fonts (Inter, Space Grotesk) are self-hosted from npm and licensed under the SIL Open Font License.

## Tests

- Unit tests use the shared MSW server from `src/shared/test/server.ts`: declare responses with `server.use(...)`. Requests without a handler fail the test.
- Render components that fetch data with `renderWithProviders` from `src/shared/test/render.tsx`.
- E2E tests run the app without MSW and stub the API with `page.route`.
